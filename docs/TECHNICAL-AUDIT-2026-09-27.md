## Реальный end-to-end прогон

Исходная база: Source 5 / RawItem 130 / Signal 21 / Opportunity 6 / Evidence 81. После live-прогона в копии: **8 / 191 / 44 / 7 / 83**. Оригинал сохранил исходные количества. SQLite integrity_check = ok, foreign_key_check не обнаружил нарушений во всех трёх проверенных базах.

1. **Source → RawItem.** Hacker News: 15 новых записей, при повторе 14 пропущены и 1 новая запись из изменившегося top-list. GitHub openai/codex и anthropics/claude-code: по 15 новых issues; повтор каждого импорта — 0 новых / 15 пропущенных. TechCrunch RSS: 15 новых, повтор — 0 / 15. Итого 61 новый RawItem. Старый example.com RSS получил 502; отключённый Reddit — 409. Настройки с localhost URL отклонены.
2. **RawItem → Signal.** Выполнено 30 реальных OpenRouter-запросов на импортированных GitHub issues, модель `meta-llama/llama-3.3-70b-instruct`: 23 принятых сигнала с точной цитатой, 1 нерелевантный материал, 6 ошибок/отклонённых ответов. Ошибки не выдаются за успешные сигналы; сырой ответ провайдера не сохранялся, поэтому нельзя надёжно разделить эти шесть случаев на timeout, JSON/schema и несовпадение цитаты. Повтор извлечения уже обработанной записи не создаёт сигнал.
3. **Normalize → Cluster → Pattern.** 23 пригодных новых сигнала; 21 старый исключён. Получен один паттерн с двумя точными участниками. Нормализация повторяется без изменения результата; ID и состав Cluster/Pattern совпадают.
4. **Pattern → Opportunity.** Реальная AI-генерация создала `cmujbxrxo0000uwak6k47nb1s`, «Проблема подключения к GitHub». Pattern: `pattern-0621571b7974673ec3cb4bd4`; Cluster: `cluster-0621571b7974673ec3cb4bd4`. Повторная генерация вернула тот же savedId с reused=true, без нового AI-вызова и дублирования записи.
5. **Evidence → Score.** Сохранены две нейтральные связи со следующими реальными публикациями: [Codex issue #48494](https://github.com/openai/codex/issues/48494) и [Claude Code issue #97484](https://github.com/anthropics/claude-code/issues/97484). Score **42**, 2 материала, 2 Source-записи, **1 хост публикаций**. Сила каждого сигнала 0.8 — оценка модели, не наблюдаемая вероятность успеха.
6. **Validation.** Получен **RESEARCH MORE**, confidence 0, snapshot из двух материалов. Это корректная ветка недостаточных данных: нужны минимум 3 материала, 2 записи источников и 2 хоста. **Реальная AI-валидация достаточного многодоменного набора не была вызвана**; её схема и защитные условия проверены unit-тестами. Результат не означает, что проблема/рынок валидированы.
7. **Очистка и восстановление.** В тестовой копии очистка evidence дала Score 0 и пустой validation snapshot; восстановление вернуло ровно исходные два signalId и Score 42; повтор восстановления добавил 0 связей. Legacy-гипотеза без provenance получает 409 вместо случайного связывания.

Семантический недостаток реально наблюдался: генератор включил две жалобы о GitHub-интеграции, но текст гипотезы сосредоточился на конкретной ошибке Codex. Цитаты и ID корректны, однако это не доказывает, что обе жалобы имеют одну причину. Prompt уточнён; детерминированной проверки логического следования между всеми утверждениями пока нет. Данные прогона не подменялись для получения красивого BUILD.

Машиночитаемые результаты: [live-run](audit/live-run-2026-09-27.json), [44 HTTP/API проверки](audit/e2e-2026-09-27.json). Эти JSON содержат статусы и идентификаторы, не ключи, базу или полные исходные документы.

## Что действительно работает сейчас

Ручной импорт поддерживаемых источников, сохранение RawItem, AI-извлечение с точной цитатой и состояниями, повторяемая нормализация, общая эвристическая кластеризация, паттерны с членством, AI-гипотеза с атомарной записью evidence/provenance/research, идемпотентная генерация, пересчитываемый Score, отображение цитат/lineage и отказ от преждевременного BUILD. Интерфейс позволяет пройти материалы → кластеры → паттерны → возможность → проверка.

Предпочтения, локальный профиль и избранное работают в localStorage; каталог использует реальные DTO. Экспорт каталога — клиентский снимок данных, не AI-исследование. Уведомления в settings честно отмечены недоступными. Статус «ключ настроен» проверяет наличие ключа, а не здоровье провайдера.

## Оставшиеся mock/hardcoded элементы

- `lib/mock-data.ts` и явный `?mode=demo`: демонстрационные карточки и оценки, отделённые от реального pipeline.
- Legacy `/reports`, `/team`, `/alerts`, `/integrations`: статические демонстрационные экраны, без соответствующих серверных систем. Интеграции не обозначаются подключёнными.
- `/simulator`: фиксированные демонстрационные коэффициенты, не AI и не финансовый прогноз.
- Порог lexical similarity 0.28, минимальные размеры групп, веса Score 40/30/30, gate 3 материала / 2 Source / 2 хоста, confidence ≥70 для BUILD: общие явно заданные эвристики. Они не являются отраслевыми словарями и не обучены на статистике успешных бизнесов.
- Фиксированные ограничения: 15 материалов за sync, 1–5 за extraction batch, 40 сигналов для генерации, 40 evidence для validation. Превышение лимита генерации отклоняется, а не скрыто обрезается.

## Ограничения и непроверенные области

- Это локальный однопользовательский MVP: нет auth/authz, rate limiting, tenant isolation. Удаление фиктивного логина не создаёт защиту API. Публичное размещение вне scope.
- Кластеризация лексическая: пропускает синонимы/разные языки, может объединить разные причины похожих жалоб. Generic bug не равен спросу; модель всё ещё иногда классифицирует обычные баги как потребность. Точность/recall не измерены на размеченной выборке.
- Цитата подтверждает происхождение текста, а не истинность утверждения, независимость автора, размер рынка, готовность платить или спрос. Разные Source-записи/домены тоже не гарантируют независимость.
- История Validation не хранится в БД; отчёт и проверенный snapshot живут на текущей странице. BUILD на реальных достаточных данных в этом прогоне не подтверждён. Отсутствующие market/customer/why-now остаются null.
- HN собирает только story title/text, не linked article/comments. GitHub — latest open issues без пагинации. RSS — содержимое feed, не полный crawler. Нет фоновой очереди, планировщика, backoff, автоматического retry failed, мониторинга или измеренного поведения под нагрузкой. Batch обрабатывает pending; failed можно повторить через single-extract API.
- Создание Source есть в API; полноценного редактора конфигурации в UI нет. Старый неверный RSS URL не переписывается скрыто и требует новой корректной конфигурации.
- Дедуп canonical URL не распознаёт зеркала/перепечатки. Старые записи и дубли сохранены для аудита; нет миграции с удалением исторических данных. При конкурентных SQLite-записях возможны явные ошибки/частичный импорт; нагрузочный тест не проводился.
- Контекст AI ограничен (извлечение 16k символов, generation 2.5k исходного текста на сигнал, validation 4k). Промпт и схемы уменьшают риск prompt injection, но не доказывают семантическую безопасность модели. Сетевые проверки URL/DNS не эквивалентны изолированному egress-прокси и не дают полной защиты от DNS rebinding.
- Provider/network ошибки возвращаются явно, но подробной диагностической истории нет. Шесть неуспешных извлечений остаются failed, не замаскированы фикстурами.
